## 1. 개요

Java Swing 기반의 **클라이언트–서버 구조 메신저**를 개발한다.
기업 사내 메신저처럼 **상대방이 접속해 있지 않아도 메시지를 보낼 수 있고**, 수신자가 나중에 접속하면 그동안 쌓인 메시지를 받아 볼 수 있도록 한다.

## 2. 기획 의도 및 배경

- 클라이언트끼리 직접 연결하는 P2P(C2C) 방식으로도 **실시간 대화**는 구현할 수 있다.
- 하지만 실제 사내 메신저에서는 다음 상황이 자주 생긴다.
  - 수신자가 **부재중(오프라인)**일 때도 메시지를 보내야 한다.
  - 발신자가 메시지를 보낸 뒤 **프로그램을 종료해도**, 수신자는 나중에 접속해서 그 메시지를 받아야 한다.
- 발신자와 수신자가 **동시에 접속해 있지 않은** 상황에서 메시지를 전달하려면 그 사이에 메시지를 보관해 줄 **항상 켜져 있는 중재자**가 필요하다.
- 그래서 메시지 전달과 보관을 맡는 **서버 프로그램**과 사용자가 쓰는 **클라이언트 프로그램**을 따로 개발한다.

## 3. 아키텍처 선택 근거

| 방식 | 실시간 대화 | 수신자 오프라인일 때 전송 | 발신자 종료 후 수신자 수신 | 비고 |
|---|---|---|---|---|
| 순수 P2P (직접 연결) | O | X | X | 둘 다 접속 중일 때만 가능 |
| P2P + 발신자 측 보관 후 재전송 | O | △ | X | 발신자가 켜져 있어야 함 |
| P2P + 다른 피어가 대신 보관 (분산 저장) | O | △ | △ | 보관할 피어가 접속 중이어야 함, 구현 복잡 |
| **클라이언트–서버 (저장 후 전달)** | **O** | **O** | **O** | **채택** |

→ 기획 의도(부재중 전송, 발신자 종료 후 수신)를 가장 확실하고 단순하게 만족하는 **클라이언트–서버 + 저장 후 전달(Store-and-Forward)** 구조를 채택한다.

## 4. 목표

**과제 제출 범위 (2026-12-11)**

- [ ] 서버 관리 화면: 관리자 로그인, 사용자 관리(추가·조회·수정·삭제), 서버 시작·중지
- [ ] 서버를 통한 메시지 송수신 (받는 사람 여러 명, 참조)
- [ ] 오프라인 사용자에게 보낸 메시지 저장 및 접속 시 전달
- [ ] 받은·보낸 내역 조회·삭제 (로컬 보관함)
- [ ] 읽음 확인과 접속 상태 표시
- [ ] 조직도 (관리 화면에서 편집, 클라이언트에 표시)
- [ ] 서식 있는 본문(글자 크기·색), 회신·전체회신

**제출 후 확장**

- [ ] 첨부파일 전송 — 제출 때는 설계 뼈대만 둠
- [ ] 전달, 나에게 보내기, 본문 속 이미지, 실시간 단체 대화방, 보관 기간 정리

## 7. 개발 일정

**진행 방식**: 설계(틀)를 먼저 확정하고, 그 위에서 기능 하나를 클라이언트부터 서버까지 끝까지 관통해 만드는 **수직 슬라이스** 방식으로 구현한다.

- 각 단계가 끝나면 실행해서 확인할 수 있고, 테스트가 있다.
- 위험한 것(네트워크, 동시성)을 앞쪽에 둔다.
- **1~5단계가 끝나면 제출 가능한 상태**가 되고, 6~7단계는 시간이 밀리면 줄일 수 있는 완충 구간이다.
- 구현 중 설계서·요구사항분석서에 정의되지 않은 부분을 발견하면 즉시 멈추고 결정한 뒤 문서에 반영하고 진행한다(설계서 5장).
