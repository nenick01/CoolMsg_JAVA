## 1. 테스트 방법

- 외부 라이브러리(JUnit)를 쓰지 않고, 각 프로젝트의 `test/` 폴더에 `main`으로 실행하는 테스트 클래스를 둔다(설계서 5장 U13).
- 테스트 결과는 줄마다 `PASS` / `FAIL`로 출력하고, 마지막에 통과·실패 개수를 보여 준다. 하나라도 실패하면 종료 코드 1로 끝난다.
- `test/` 폴더는 Eclipse·VS Code에서 **테스트 소스**로 등록되어, 서버·클라이언트 실행 파일에는 포함되지 않는다.

| 테스트 | 실행 방법 |
|---|---|
| Common | VS Code `Run and Debug` → `Test: Common` / Eclipse에서 `CoolMSG_JAVA_Common/test/coolmsg/common/CommonTest.java` → Run As → Java Application |
| Client | VS Code `Run and Debug` → `Test: Client` / Eclipse에서 `CoolMSG_JAVA_Client/test/coolmsg/client/ClientTest.java` → Run As → Java Application |
| Server | VS Code `Run and Debug` → `Test: Server` / Eclipse에서 `CoolMSG_JAVA_Server/test/coolmsg/server/ServerTest.java` → Run As → Java Application (작업 폴더: `CoolMSG_JAVA_Server`) |

### 4.8 테스트를 고친 기록

- **문제**: 서버 테스트를 처음 한 번은 통과했지만 다시 실행하면 "형식 오류가 로그에 이유와 함께 남음"이 가끔 실패했다.
- **원인**: 서버는 연결을 닫을 때 ① 세션 목록에서 빼고 ② 로그를 남긴다. 테스트는 "세션 목록이 비기"를 기다린 뒤 바로 로그를 확인해서, ①과 ② 사이를 보면 실패했다. **서버가 아니라 테스트의 기다리는 조건이 틀렸다.** 시간 초과 검사도 같은 문제가 있었는데 운 좋게 통과하고 있었다.
- **해결**: 테스트가 **확인하려는 것(로그 줄) 자체**를 기다리도록 바꿨다. 이후 8회 반복 실행 모두 통과.
- **배운 점**: 다른 스레드의 결과를 확인할 때는 "끝났을 것 같은 다른 신호"가 아니라 확인하려는 조건 자체를 기다린다.

| 정상 | 같은 `MSG`가 다시 옴 | 저장하지 않고 `ACK`만 |
| 정상 | 이름 표시 | `김철수`, 목록에 없는 아이디는 그대로, "이영희 외 1명" |
| 예외 | 보내기 전 검사: 받는 사람 없음, 공백뿐인 본문, HTML로 바꾼 크기 1MB 초과 | 안내 문장 (서버에 보내지 않음) |

### 6.6 테스트를 고친 기록

- 3단계 검사 "로그인 후 `SEND` → 지원하지 않는 기능"(5.1)은 4단계에서 `SEND`를 구현해 기대가 바뀌었다. 아직 없는 `STATUS`(5단계)로 바꿔 "로그인 후에는 '로그인 필요'가 아니라 '지원하지 않는 기능'"을 계속 확인한다.
- `LockStripes` 검사를 처음에는 "키 1000개면 잠금 64개를 모두 쓴다"로 썼는데 실패했다. `"key0"`~`"key999"`처럼 비슷한 문자열은 해시값의 아래쪽 비트가 몰리기 때문이다. 검사할 것은 "64개를 넘지 않는다"였으므로 기대를 고치고, 실제 키 형식(UUID)으로 바꿨다. 코드도 `HashMap`처럼 위쪽 비트를 섞도록 고쳤다.
