과제 요구사항 "테스트 기록: 정상 동작 사례와 오류·예외 처리 확인 내용"에 대응하는 문서다. 기능을 구현할 때마다 이 문서에 기록을 더한다.

---

## 1. 테스트 방법

- 외부 라이브러리(JUnit)를 쓰지 않고, 각 프로젝트의 `test/` 폴더에 `main`으로 실행하는 테스트 클래스를 둔다(설계서 5장 U13).
- 테스트 결과는 줄마다 `PASS` / `FAIL`로 출력하고, 마지막에 통과·실패 개수를 보여 준다. 하나라도 실패하면 종료 코드 1로 끝난다.
- `test/` 폴더는 Eclipse·VS Code에서 **테스트 소스**로 등록되어, 서버·클라이언트 실행 파일에는 포함되지 않는다.

| 테스트 | 실행 방법 |
|---|---|
| Common | VS Code `Run and Debug` → `Test: Common` / Eclipse에서 `CoolMSG_JAVA_Common/test/coolmsg/common/CommonTest.java` → Run As → Java Application |
| Server | VS Code `Run and Debug` → `Test: Server` / Eclipse에서 `CoolMSG_JAVA_Server/test/coolmsg/server/ServerTest.java` → Run As → Java Application (작업 폴더: `CoolMSG_JAVA_Server`) |

### 2.1 HeaderFormat — 헤더 규칙 U1 (12개)

| 구분 | 확인한 내용 | 기대 결과 |
|---|---|---|
| 정상 | 맵을 쓰고 다시 읽기 | 순서·값이 그대로 |
| 정상 | 값 안의 `=` (`reason=x=y=z`) | 첫 `=`에서만 나눠 값은 `x=y=z` |
| 정상 | 빈 문자열 읽기 | 빈 맵 |
| 예외 | 같은 키 두 번, `\r\n` 줄바꿈, `=` 없는 줄, 키가 빈 줄, 중간 빈 줄, 마지막 줄에 `\n` 없음 | `FormatException` |
| 예외 | 값에 줄바꿈을 넣어 쓰기 | 쓰기 전에 `IllegalArgumentException` |
| 예외 | 깨진 UTF-8 바이트 | `FormatException` (`?`로 조용히 바꾸지 않음) |

### 2.2 Packet — 헤더 검사, 응답, 로그 (15개)

| 구분 | 확인한 내용 | 기대 결과 |
|---|---|---|
| 정상 | `LOGIN` 패킷의 종류와 `reqId` | `LOGIN`, 3 |
| 정상 | 로그용 `toString()` | 비밀번호가 `****`로 가려짐 |
| 정상 | `replyTo(요청, 종류)` | 요청의 `reqId`가 응답에 그대로 |
| 정상 | 목록 넣기·읽기 (`receivers=lee,park`) | `[lee, park]`, 없는 키는 빈 목록 |
| 정상 | `setData` 후 원본 배열을 고침 | 패킷 데이터는 바뀌지 않음 (복사본 저장) |
| 정상 | `PING`·`LOGIN`만 로그인 전 허용, 응답 패킷은 요청이 아님, 모르는 이름은 `null` | 설계서 2.3과 같음 |
| 예외 | `type` 키를 `put`, 값에 줄바꿈, 목록 항목에 쉼표 | `IllegalArgumentException` |
| 예외 | 없는 필수 키, 정수가 아닌 `reqId` | `FormatException` |

### 2.3 PacketReader / PacketWriter — 패킷 경계 (16개)

| 구분 | 확인한 내용 | 기대 결과 |
|---|---|---|
| 정상 | 설계 예시 `SEND` 패킷(한글 본문) 쓰기 | **전체 206바이트**, 앞 4바이트 `00 00 00 86`(헤더 134), 본문 40글자 = 64바이트 |
| 정상 | 쓰고 다시 읽기 | 종류·헤더·본문이 같음 |
| 정상 | 본문에 빈 줄과 `=`가 있는 패킷 두 개를 이어 쓰고 읽기 | 두 패킷을 정확히 나눠 읽음 |
| 정상 | 모르는 종류(`SNED`) | 예외 없이 읽고 `getType()`=`null`, `reqId` 유지 (서버가 `ERROR`로 응답하기 위해) |
| 예외 | 더 읽을 패킷 없음, 패킷 중간에 끊김 | `EOFException` |
| 예외 | 헤더 길이 0, 헤더 64KB 초과, 데이터 길이 음수, 데이터 11MB 초과 | `FormatException` (메모리 폭주 방지) |
| 예외 | 첫 줄이 `type=`이 아님, 헤더에 같은 키 두 번 | `FormatException` |
| 예외 | 데이터 11MB 초과 패킷 쓰기 | 보내기 전에 `IllegalArgumentException` |

### 2.4 HeaderBodyFile — 메시지 파일 형식 (8개)

| 구분 | 확인한 내용 | 기대 결과 |
|---|---|---|
| 정상 | 없는 폴더 아래에 저장 후 읽기 | 폴더 자동 생성, 머리글 순서·값과 본문(빈 줄·`=` 포함)이 그대로 |
| 정상 | 값을 바꾸고 새 키를 더해 다시 저장 | 바꾼 키는 자리 유지, 새 키는 맨 뒤 |
| 정상 | 머리글 없이 본문만 / 본문이 빈 파일 | 각각 올바르게 읽음 |
| 예외 | 머리글 끝 빈 줄 없음, 깨진 UTF-8 파일 | `FormatException` (파일 이름 포함) |
| 예외 | 없는 파일 | `IOException` |

### 2.7 model — 상태, 첨부 정보, 메시지 (13개)

| 구분 | 확인한 내용 | 기대 결과 |
|---|---|---|
| 정상 | `DeliveryState`: READ가 DELIVERED보다 앞섬, 같은 상태·뒤 상태는 반영 안 함, 기록 없으면 반영 | "상태는 앞으로만" 규칙(설계서 2.6) |
| 정상 | 첨부 정보의 파일 이름에 `\|`와 `,` | 이름으로 그대로 유지, 다시 헤더 값으로 같음 |
| 정상 | `SEND`용 메시지의 헤더 | `sender`·`sentAt`·`cc` 줄이 생기지 않음 |
| 정상 | 메시지 → 파일(서버 전용 키 추가) → 메시지 | 모든 값 복원, 서버 전용 키는 무시 |
| 정상 | `replyTo` 왕복 | 같은 값 |
| 예외 | 첨부 정보 칸 부족, 크기가 숫자가 아님, `messageId` 없음, `sentAt` 형식 틀림 | `FormatException` |
| 예외 | 받는 사람 목록에 항목 추가 | `UnsupportedOperationException` (읽기 전용) |

모든 테스트는 임시 폴더에 파일을 만들어 확인한다. 실제 `config/` 파일은 예시 `server.txt`를 읽기만 한다.

### 3.1 ServerConfig — `server.txt` 읽기와 값 검사 (8개, 설계서 U11·U21)

| 구분 | 확인한 내용 | 기대 결과 |
|---|---|---|
| 정상 | 파일 없음 | 모두 기본값(포트 9000 등) + 경고 1개 |
| 정상 | `\r\n` 줄바꿈, 앞뒤 공백, 주석, 빈 줄 | 관대하게 읽음 (사람이 고치는 파일) |
| 정상 | 적지 않은 항목 | 기본값 |
| 정상 | 경계값(포트 1024·65535, 첨부 1MB) | 허용 |
| 정상 | 저장소의 예시 `config/server.txt` | 경고 없이 읽힘 |
| 예외 | 포트 80, 보관 기간 0, 숫자 아님, 첨부 50MB, 빈 서버 이름 | **그 항목만** 기본값 + 항목마다 경고 |
| 예외 | 같은 키 두 번 | 나중 값 + 경고 |
| 예외 | 모르는 키, `=` 없는 줄 | 무시 + 경고 |

### 3.2 UserDirectory — `users.txt` 읽기 (6개)

| 구분 | 확인한 내용 | 기대 결과 |
|---|---|---|
| 정상 | 파일 없음 | 빈 목록 + 경고 |
| 정상 | 4칸(active로 봄)·5칸(deleted)·`\r\n` 줄 | 모두 읽음, 등록 순서 유지 |
| 예외 | 아이디 형식 오류, 3자 미만 아이디, 중복 아이디, 칸 수 오류, 상태 값 오류 | 그 줄만 건너뜀 + 줄마다 경고 |
| 예외 | 목록 복사본에 항목 추가 | `UnsupportedOperationException` (원본 보호) |
| 예외 | UTF-8이 아닌 파일 | `IOException` → 서버 시작 중단 (U22) |

### 3.3 UserDirectory — 추가·수정·초기화·삭제·복구 (26개, REQ-F-204~206·212, U17~U19)

| 구분 | 확인한 내용 | 기대 결과 |
|---|---|---|
| 정상 | 이름 앞뒤에 공백이 있는 사용자 추가 | 공백 제거, 등록 순서 맨 뒤, 바로 로그인 가능 |
| 정상 | 경계값: 아이디 3자·20자, 이름 20자 | 허용 |
| 정상 | 이름 수정 | 바뀐 이름 |
| 정상 | 비밀번호 초기화 | 새 비밀번호만 통과, 예전 비밀번호 거부 |
| 정상 | 삭제 | 목록에 '삭제됨'으로 남고 로그인 불가 |
| 정상 | 복구 | 활성, **새 비밀번호만** 통과, 등록 순서 자리 그대로 |
| 예외 | 아이디 2자·21자·대문자·한글 | `UserDirectoryException` |
| 예외 | 이름 공백뿐·21자·`\|` 포함 | `UserDirectoryException` (`\|`는 파일 칸을 깨뜨림) |
| 예외 | 비밀번호 3자, 두 비밀번호 불일치 | `UserDirectoryException` |
| 예외 | 이미 있는 아이디, **삭제된 아이디로 다시 추가** | `UserDirectoryException` (아이디 재사용 금지, 결정 14) |
| 예외 | 삭제된 사용자의 이름 수정·비밀번호 초기화·다시 삭제, 삭제되지 않은 사용자 복구 | `UserDirectoryException` |
| 예외 | 없는 아이디 수정, 없는 아이디·틀린 비밀번호로 로그인 확인 | 거부 / `false` |

### 3.4 UserDirectory — 파일 저장 (8개, U20)

| 구분 | 확인한 내용 | 기대 결과 |
|---|---|---|

| 정상 | 다시 읽기 (프로그램 재실행) | 같은 목록·상태·비밀번호 |
